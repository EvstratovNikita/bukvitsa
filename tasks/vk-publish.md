# Публикация «Буквицы» в VK Mini Apps

Что уже сделано в коде и что осталось сделать руками в кабинете разработчика.

---

## Что готово в проекте

| | |
|---|---|
| Мост с площадкой | `src/lib/vk.js` — init, хранилище, реклама, данные игрока |
| Прогресс | облако VK, снимок режется на части (лимит ключа) — `bkv_meta`, `bkv_0…N` |
| Экономика | локальная, как на Яндексе: Supabase из сборки вырезан |
| Реклама | `VKWebAppShowNativeAds` за энергию и удвоение монет |
| Таблица лидеров | общая, на нашем Supabase (`supabase/vk_leaderboard.sql`, подпись VK проверяется на сервере); нативное окно «Среди друзей» — кнопкой внутри |
| Сборка | `npm run build:vk` → `dist/` + `buklitsa-vk.zip` |
| Деплой | `npm run deploy:vk:dev` (только dev, без пуша) и `npm run deploy:vk:auto` (dev + боевой) — см. «Заливка обновлений» |
| Материалы | `vk-assets/` — иконки и скриншоты |

---

## Шаг 1. Создать приложение

1. Открыть **dev.vk.com** → «Мои приложения» → **Создать приложение**.
2. Тип — **Игра** (не «Мини-приложение»: у игр свой раздел каталога и свои
   правила монетизации).
3. Название — **Буквица**, категория — головоломки/слова.
4. После создания записать **ID приложения** — он понадобится дальше.

## Шаг 1а. Поднять общую таблицу лидеров

Нативное окно VK сравнивает игрока только с друзьями, поэтому общий рейтинг
живёт у нас в Supabase (том же проекте, что и веб-версия).

1. Supabase → **SQL Editor** → выполнить `supabase/vk_leaderboard.sql`.
   В конце должны напечататься три «ok» — это самопроверка подписи.
2. Там же, одним запросом, положить **защищённый ключ** приложения VK
   (настройки приложения → «Защищённый ключ»):

```sql
insert into private.app_secrets (name, value)
values ('vk_client_secret', 'СЮДА_КЛЮЧ')
on conflict (name) do update set value = excluded.value;
```

   Ключ нигде больше не хранится: ни в репозитории, ни в сборке. Именно им
   сервер проверяет, что результат прислал тот игрок, за которого он себя
   выдаёт.

3. Создать файл `.env.vk.local` (в репозиторий не попадает) с адресом проекта
   и **публикуемым** ключом — теми же, что в `.env.local` веб-версии:

```
VITE_SCORES_URL=https://<ref>.supabase.co
VITE_SCORES_KEY=sb_publishable_...
```

   Без этого файла сборка соберётся, но пункт «Лучшие игроки» в меню не
   появится — так и задумано, пустое окно хуже отсутствующего пункта.

## Шаг 2. Прописать ID и залить сборку

1. Вписать ID в `vk-hosting-config.json` вместо `ЗАПОЛНИТЬ_ID_ПРИЛОЖЕНИЯ`.
2. Выполнить:

```bash
npm run deploy:vk
```

Команда соберёт `--mode vk` (Supabase вырезан, тег SDK Яндекса убран),
проверит результат и зальёт `dist/` на **dev-хостинг** VK.

Если удобнее руками: в настройках приложения есть раздел «Хостинг», туда
загружается `buklitsa-vk.zip` — он лежит в корне проекта после сборки.

3. Проверить игру по dev-ссылке из кабинета. Убедиться, что:
   - игра открывается и на десктопе, и в мобильном VK;
   - прогресс переживает перезаход (сыграть партию, закрыть, открыть снова);
   - в меню нет строки входа по почте — её там быть не должно.

4. Когда всё в порядке — в кабинете перевести сборку из dev в **production**.

## Шаг 3. Заполнить карточку

Из папки `vk-assets/`:

- **иконки** (раздел «Оформление»): универсальная — `icon-576.png`,
  каталог и сниппеты — `icon-278.png`, маленькая — `icon-150.png`,
  фавикон — `icon-32.png` (3 КБ при лимите 50). Все сделаны из логотипа
  с совой `owl-logo-512-source.png` (тот же, что на Яндексе): 576, 278 и 150 —
  логотип целиком, 32 — мордочка совы крупным планом, иначе плитки
  с названием сливаются в полосу. Каталожную VK разрешает менять не чаще
  2 раз в 2 недели;
- **большой сниппет** (раздел «Оформление» → «Изображения») —
  `snippet-1120x630.png`, из плаката с совой; название вверху, потому что
  низ картинки VK перекрывает своим текстом;
- **скриншоты** — ориентация **книжная**, пять файлов по порядку:
  `vk-promo-1-main`, `-2-pet`, `-3-modes`, `-4-bgs`, `-5-mini` (600×1200).
  Это маркетинговые снимки, сделанные для Яндекса (`Desktop/Буквица/скрины/маркетинг`):
  крупный интерфейс в рамке, заголовок, фирменный фон. Из 1080×1920 срезано
  по 60 px с боков — получается ровно 1:2, рамка начинается на x=72 и не
  задевается. Ориентацию выбирают один раз: при смене VK удаляет уже загруженные.

Тексты — в `vk-assets/description.md`.

> Точные размеры изображений форма показывает при загрузке. Если попросит
> что-то, чего в папке нет, — скажите, пересниму: и иконки, и скриншоты
> генерируются из настоящей сборки, размер задаётся одним параметром.

## Шаг 4. Отправить на модерацию

Что смотрят: игра открывается без ошибок, нет битых ссылок и заглушек, контент
соответствует заявленной категории и возрастному рейтингу, скриншоты
показывают саму игру.

Наши слабые места закрыты заранее: шрифты внутри сборки (внешних запросов
нет), Supabase не вызывается, тега чужого SDK нет.

## Шаг 5. Включить монетизацию

Реклама в коде уже подключена, но показы начнутся только после того, как VK
одобрит монетизацию приложения. До этого `VKWebAppShowNativeAds` отвечает
отказом, игра это переживает штатно: награда не начисляется, кнопка просто не
срабатывает.

После одобрения проверить оба места: «посмотреть рекламу» за энергию и
«удвоить награду» после победы.

Проверено 11 сентября: межстраничная реклама показывается, а на ролик за
награду VK отвечает `client_error · 20 · No ads` — роликов этого формата для
игры пока нет. Вызов верный, игрок видит «Сейчас нет рекламы — попробуйте
позже». Заполнение обычно появляется после публикации в каталоге и чаще в
мобильном приложении VK, чем в браузере. Причина последнего отказа — в
консоли фрейма игры: `__buklitsaCloud.ads`.

## Что осталось за кадром

- **Таблица лидеров.** Общая, на нашем сервере: счёт присылает клиент, сервер
  проверяет подпись launch-параметров VK, рост монотонный, с потолком. От
  накрутки собственного счёта это не защищает — для этого нужна серверная
  проверка слов.
- **Время на устройстве.** Суточные кулдауны мини-игр и восстановление энергии
  считаются по часам устройства — как и на Яндексе. Игрок, переводящий время
  вперёд, ускоряет и то и другое. Чинится только переносом счёта времени на
  сторону площадки.
- **Лимит ключа хранилища.** Разбивка рассчитана на снимок до 18 000 символов
  (12 частей). Сейчас снимок ~2 900 символов, запас многократный, но если
  когда-нибудь упрёмся — сборка не молчит: `cloudSave` вернёт ошибку с текстом
  «снимок не помещается».

## Заливка обновлений

Две команды, обе без вопросов (токен деплоя уже сохранён):

```bash
npm run deploy:vk:dev
```

Только dev-адрес. Пуша на телефон нет. Новую версию видят все
администраторы, у которых в «Размещении» включён «Режим разработки»
(включён для Web, мобильной версии и мобильного приложения); игроки
остаются на прежней боевой версии. Использовать, пока правим и проверяем.

```bash
npm run deploy:vk:auto
```

Dev и боевой адрес. VK присылает пуш на телефон создателю — смену боевого
адреса надо подтвердить. Использовать один раз, когда версия проверена.

Адреса в «Размещении» руками не править: у каждой заливки свой хвост
адреса, и деплой переписывает поля сам.
