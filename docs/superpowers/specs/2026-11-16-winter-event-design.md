# Ивент «Снежная ночь» (Новый год 2026/27) — дизайн

Дата: 16.11.2026. Цель — попасть в новогоднюю подборку VK (30.12.2026 – 10.01.2027).

## Зачем и сроки

- Фичеринг VK даёт тысячи новых игроков. Праздничную заявку без оформления и праздничных
  товаров отклоняют.
- «Загадки ночи» на Хэллоуин игрокам понравились, поэтому механику повторяем в зимней теме.
  Добавляем усложнённый режим «Ледяная гонка».
- **До 1.12** ивент в боевой сборке VK/OK/Яндекс, выключен по дате. Редакция видит его
  предпросмотром `vk.com/app54762016#winter`.
- **2.12** подаём заявку `Фичеринг: Новый год: ВКонтакте`. По документации подавать можно
  не раньше чем за 3 недели (то есть с 9.12). Если заявку вернут как раннюю, отправим повторно 9.12.
- Работаем в ветке `winter`. В main вливаем, когда ивент готов: после каждого изменения main
  идёт деплой на боевой VK.

## Цели, не-цели, анти-цели

- **Цели:**
  - зимние загадки по образцу Хэллоуина;
  - «Ледяная гонка с оттепелью»;
  - зимние награды: наряды, стиль клеток, фоны;
  - достижения;
  - праздничное оформление меню;
  - общий движок, чтобы следующие праздники (14.02, 8.03) делались за дни.
- **Не-цели:**
  - серверная часть для веба: ивент только на площадках (`isEmbedded`), как Хэллоуин;
  - покупки за голоса;
  - VK-миссии;
  - звуки ивента.
- **Анти-цели:**
  - сломать то, что игроки получили на Хэллоуин: наряды, фоны, стиль клеток, достижения,
    сохранения;
  - гонка, которую медленный игрок не может выиграть в принципе;
  - падение плавности меню на слабых телефонах.

## Подходы (выбран B)

- **A. Копия хэллоуинского кода под зиму.** Быстрый старт, но две параллельные ветки кода,
  и с каждым праздником их больше.
- **B. Общий движок сезонных ивентов** — выбран пользователем. Хэллоуин и зима становятся
  описаниями (контент, награды, тема), логика общая. Стоит около дня на перенос Хэллоуина
  и тесты совместимости, зато следующие праздники быстрые.
- **C. Новый движок только для зимы.** Хэллоуин в безопасности, но два механизма вместо одного.

## 1. Движок

### Календарь — `src/lib/events.js`

```js
export const EVENTS = [HALLOWEEN, WINTER];
// WINTER = { id: 'winter', start: 2026-12-26 00:00 МСК, end: 2027-01-12 00:00 МСК, endLabel: '11.01' }
activeEvent(now)        // событие, у которого окно открыто или включён предпросмотр; иначе null
eventActive(id, now)
eventDaysLeft(id, now)
```

- **Предпросмотр:** `#<id>`, `?event=<id>`, `#<id>-off` и `VITE_EVENT_PREVIEW=<id>`. Механика
  та же, что у Хэллоуина сейчас, только параметризована. В sessionStorage хранится id события.
- `halloweenActive()` и родственные функции остаются тонкими обёртками или заменяются. Ни одна
  дата не дублируется вне `EVENTS`.

### Описание события — `src/data/events/<id>.js`

```js
{
  id, title: 'Снежная ночь', modeTitle: 'Зимние загадки',
  currency: { icon: 'snowflake', one: 'снежинка', few: 'снежинки', many: 'снежинок' },
  riddles: [{ word, riddle }],
  track: [{ id, need, kind: 'deco'|'shop'|'coins', ref?, amount?, grand? }],
  dailyCap, capXpPerUnit,
  achievementsTab: 'winter',
  theme: { tokens: { '--ev-a': …, '--ev-b': … }, decor: 'snow' | 'bats' },
  ice?: { … }   // только у зимы, см. §3
}
```

- `src/data/halloween.js` переезжает в `src/data/events/halloween.js` без изменения значений.

### Прогресс — `src/lib/eventProgress.js`

Это `halloweenProgress.js`, параметризованный описанием события:

- `normalize`, `applyResult`, `merge`, `nextRiddle`, `dueSteps`;
- `restoreEventItems` идёт по предметам **всех** событий.

**Хранилище** — `stats[event.id]`. Форма та же, что у `stats.halloween` сейчас:
`earned`, `dayKey`, `dayEarned`, `solved`, `firstTry`, `seen`, `steps`, `bought`.

- `stats.halloween` остаётся как есть, вместе с полем `pumpkins` и `LEGACY_STEPS`.
- У зимы добавляются `iceWins` и `iceBest` — лучший запас строк. `merge` берёт их по максимуму.

### Режим в `useGame.js`

- `gameMode` — id события (`'halloween'` / `'winter'`). Старые сохранения с `'halloween'`
  читаются как раньше.
- Варианту гонки добавляется флаг раунда `ice: true`.
- Полки: `rounds.ev` для загадки, `rounds.ice` для гонки. Старый ключ `rounds.hw` читается
  ради совместимости.
- `startEvent({ ice })`, `nextEventRiddle()`, `exitEvent()` заменяют хэллоуинские функции.
  Поведение то же:
  - энергия не тратится;
  - интерстишл — как у «Новой игры»;
  - `recordWin(…, creditCoins=false)`, опыт Букле;
  - `rememberWord` не вызывается;
  - после конца события отложенная партия выбрасывается.
- `lastHw` → `lastEvent`.

### Интерфейс — `src/components/Event/*`

- `EventBanner`, `EventModal`, `EventGame` (карточка загадки, шкала, панель конца партии),
  `EventIcons` — из `Halloween/*`, а тексты, иконки и цвета берутся из описания события.
- CSS: `.hw-*` → `.ev-*` на токенах `--ev-a`, `--ev-b`, `--ev-ink`. Для каждого события свои
  значения в светлой и тёмной теме.
- Декор меню — слой `decor: 'bats' | 'snow'`.

### Магазин, гардероб, достижения

- Предметы с `source: 'track'` любого события нельзя купить (`'locked'`).
- Некупленные и неполученные предметы скрыты вне окна события, полученные остаются навсегда.
- Вкладка достижений события видна во время события, а после — только если в ней что-то открыто.

## 2. Зимний контент

### Загадки

- ~50 записей `{ word, riddle }`, 4–6 букв, ё → е. Каждое слово проходит `isValidWord`;
  если не проходит, добавляется в `EXTRA_GUESSES`. Проверяется скриптом.
- **Слова** — общеизвестные и тёплые, только 4–6 букв: елка, снег, санки, иней, вьюга, шарф,
  каток, лыжи, сугроб, мороз, метель, сосулька (нет — 8), снежок, шапка, валенок (нет — 7),
  гирлянда (нет), мишура, свечи, сани, олень, пингвин (нет)… Слова длиннее 6 букв отсеивает
  тот же скрипт проверки.
- **Загадки** — одна строка до ~70 символов, описательные, не в рифму. Никакой религии
  (правило Playgama 4.1): «Рождество» и подобное не используем.
- **Порядок колоды:** первыми идут самые узнаваемые слова, длины чередуются.

### Лента «Снежинки»

За обычную загадку 3/2/1 снежинки (1–2 / 3–4 / 5–6 попыток), за гонку вдвое больше.
Дневной лимит `dailyCap` = 12. Ивент длится 17 дней, поэтому конец ленты ставим на ~90:
при игре каждый день на максимум он берётся за 8 дней, при игре через день — к концу ивента.

| ❄ | Награда | Вид |
|---|---|---|
| 6 | Брошь «Варежка» (+1) | наряд |
| 14 | Шарф (+2) | наряд |
| 24 | Стиль клеток «Иней» | магазин |
| 35 | Фон «Снежное утро» (светлый) | магазин |
| 47 | Амулет «Гирлянда» (+2) | наряд |
| 60 | 100 монет | монеты |
| 74 | Фон «Звёздная зима» (тёмный) | магазин |
| 90 | Шапка-ушанка (+3), главный приз | наряд |

Цифры — моя оценка темпа. Их проверяем в предпросмотре и правим в одном месте.

### Арт

Всё рисуется в SVG по правилам Хэллоуина: старые координаты `SLOT_POSITIONS`, без SVG-фильтров
и без анимаций внутри SVG.

- **Наряды:**
  - ушанка: мех и завязки;
  - шарф: полоски, концы свисают;
  - варежка-брошь: узор-снежинка;
  - гирлянда-амулет: 4–5 огоньков с ореолами-кругами.
- **Стиль клеток «Иней»:**
  - «не на месте» — ледяной голубой вместо жёлтого, с зелёным не путается;
  - «на месте» — хвойно-зелёный с серебристой каймой;
  - контраст проверяется в обеих темах.
- **Фоны:** узоры `enc()` + `<use>`, приглушённые.
  - «Звёздная зима» — тёмно-синее небо, звёзды, снежинки;
  - «Снежное утро» — бело-голубое, сугробы, ветки ели.

### Оформление

- **Токены:** `--ev-a` — ледяной голубой, `--ev-b` — праздничный красный или золото.
- **Плашка** «❄ Снежная ночь · до 11.01».
- **Декор меню:** 8–12 снежинок падают через transform/opacity на отдельном слое.
  `prefers-reduced-motion` их останавливает. Под экраном Букли и полем декор не рисуется.
- **Иконки** в формате GameIcon без эмодзи, чтобы сборка для Playgama не ломалась.

### Достижения — вкладка «Зима»

| id | Название | Условие | Монеты |
|---|---|---|---|
| w_first | Первая снежинка | Разгадай первую зимнюю загадку | 10 |
| w_solver | Знаток зимы | Разгадай 15 зимних загадок | 40 |
| w_seer | Ледяная ясность | Разгадай загадку с первой попытки | 30 |
| w_ice | Ледокол | Выиграй «Ледяную гонку» | 40 |
| w_path | Хозяйка зимы | Пройди ленту до конца | 100 |

## 3. «Ледяная гонка с оттепелью»

Отдельная карточка «Ледяная загадка» в окне ивента и в «Режимах», рядом с обычными загадками.
Слово и загадка берутся из той же колоды.

### Правила

- В поле 6 строк. Уровень льда `L` (замёрзшие строки снизу) начинается с 0.
- Каждые `T = 30 с` активной игры `L += 1`. Замёрзшую строку использовать нельзя.
- **Оттепель:** каждая позиция, которая впервые стала зелёной, даёт `L = max(0, L − 1)`.
  Одна догадка с двумя новыми зелёными опускает лёд на две строки.
- **Поражение:** `6 − L ≤ guesses.length`, то есть лёд дошёл до строки ввода. Слово и загадка
  показываются, как при обычном проигрыше.
- **Победа:** снежинки ×2 в пределах дневного лимита, учёт `iceWins` и `iceBest`
  (сколько строк осталось свободными).
- **Подсказки** работают как в обычной партии.

### Таймер

- Отсчёт начинается с первой введённой буквы. До неё на поле подпись «Лёд проснётся с первой
  буквой».
- **Пауза:** вкладка скрыта, идёт реклама, открыто любое окно, Bridge/VK присылает
  `PAUSE_STATE_CHANGED`. Учитывается только активное время.
- **Сохранение и перезагрузка:** в раунд пишутся `L` и прошедшее время текущего интервала.
  После перезагрузки гонка стоит на паузе до первого касания: «Продолжить».
- **Выход** через «Режимы» или «Выйти»: раунд ложится на полку `rounds.ice` вместе с этим
  состоянием, лёд не тает и не растёт.

### Вид

- Замёрзшие строки покрыты слоем льда: градиент и узор инея, без фильтров.
- Лёд поднимается анимацией transform по высоте строки, ~400 мс. При reduced-motion
  строка меняется сразу.
- Над льдом — тонкая полоска, показывающая время до следующей строки.
- Оттепель: лёд опускается, на зелёных клетках короткая искра (opacity).
- В верхней панели вместо энергии — снежинки и значок гонки.

### Настройка

`ice: { secondsPerRow: 30, thawPerGreen: 1 }` в описании события. Пользователь хочет посмотреть
в деле и поправить, поэтому числа не разбросаны по коду.

## 4. Порядок работ (до 30.11)

1. Движок и перенос Хэллоуина. Тесты совместимости на снимках сохранений с хэллоуинскими
   данными. Регресс: предпросмотр `#halloween` выглядит и работает как раньше.
2. Зимний контент: слова, загадки, лента, достижения.
3. Арт: наряды, стиль клеток, фоны, декор, иконки.
4. «Ледяная гонка».
5. Проверка (§5) → влить в main → `build:yandex`, `deploy:vk:auto` → проверить
   предпросмотр `#winter` на боевом VK → скриншоты для заявки.

## 5. Проверка

- **Юнит-тесты:**
  - `activeEvent` на границах обоих окон и с предпросмотром;
  - normalize, merge и applyResult для обоих событий;
  - чтение старых `stats.halloween`, `rounds.hw` и `gameMode: 'halloween'` после конца ивента;
  - `restoreEventItems` по обоим событиям;
  - гонка как чистая функция `iceStep(state, event)`: рост, оттепель, поражение на границе,
    пауза.
- **Словарь:** скрипт проверяет все зимние слова через `isValidWord`.
- **Браузер:** 393×873 и десктоп, обе темы, `#winter`:
  - меню, окно ивента, загадка, победа с наградой, гонка до победы и до поражения;
  - пауза на рекламе и в окне, перезагрузка посреди гонки;
  - наряды, магазин, достижения;
  - без предпросмотра ивента не видно; `#halloween` по-прежнему цел.
- **Производительность:** доля занятости главного потока в меню со снегом не хуже, чем
  с летучими мышами (CPU 4x, пинг MessageChannel).
- **Сборки:** `build:vk`, `build:yandex`, сборка Playgama (ветка `english` — после слияния,
  если пользователь решит).
